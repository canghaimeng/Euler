# Euler 使用指南：启动研究、理解进展与继续探索

Euler 是一个旨在增进研究者对数学研究与推导全过程的把握和理解的智能体系统。它将命题、假设、证明依赖、候选路线、失败路径与验证证据保存在团队共享的结构化研究状态中，使研究者能够看清已经建立了什么、仍缺少哪些前提、某条路线为何受阻，以及每一步结论由哪些依据支持。同一结构化表征也为 Agent 团队提供明确的依赖关系、相关上下文与证据边界，旨在增强模型的推理能力和团队协作效果。通过可视化工作台，研究者可以快速梳理 Agent 的研究路线和关键转折，针对具体数学对象追问，也可以将团队恢复到某个节点关联的已保存状态，在独立工作区开展人工干预与后续探索。即使最终问题尚未解决，局部结论、失败记录和未解决问题仍可供理解、检查与继续研究使用。

本指南介绍如何配置并启动团队、理解网页中的研究进展，以及通过对话和里程碑恢复继续研究。示例使用 Codex 作为主 Agent 负责规划与协调，Grok 作为助手负责核查与探索；这是本指南采用的一种团队配置。

下面采用一条具体的部署路径：一台 Mac 或 Linux 电脑运行 Euler 和各个 Agent，浏览器在本机或另一台电脑上显示工作台。Euler 的研究案例包括 Nikoghosyan 猜想、Lewis–Overton 猜想和 Jankiewicz–Norin–Wise（JNW）问题；本指南后续以欧几里得素数无穷定理作为熟悉操作流程的入门示例。

## 1. 第一个项目之前需要准备什么

- **一台 Mac 或 Linux 电脑**。Mac 可以直接配置并运行整个团队。Linux 使用 Landlock ABI 3+；macOS 使用系统的 `sandbox-exec`（Seatbelt）隔离分支文件，缺失时会明确报错。
- **Python 3.10 或更高版本、Git**，以及所选 CLI 自身需要的运行环境。使用 npm 安装 CLI 时还需符合该 CLI 要求的 Node.js 版本。
- **安装你选用的 CLI 并登录**：Codex、Claude Code、Gemini CLI、Grok、Cursor Agent 可以混合组队，不必全部安装。
- **模型额度**：你可以自行设置团队各成员的使用上限，避免 Token 浪费或超额使用。

在 Mac 上可以先用 Homebrew 准备基础工具：

```bash
brew install python git
```

安装 Euler 后运行 `euler-team doctor`，检查当前系统的隔离能力和五种 CLI 的可用情况；此命令不会调用模型。

## 2. 安装 Euler

你可以将本页内容连同 [Euler 的 GitHub 仓库地址](https://github.com/canghaimeng/Euler) 一起交给 Codex、Claude Code 等 coding agent，让它们根据你的操作系统和团队需求完成安装与配置。以下为手动安装方法与常用参数介绍。

在运行团队的 Mac 或 Linux 电脑上执行：

```bash
git clone https://github.com/canghaimeng/Euler.git
cd Euler
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[gateway,observability]'
```

这会安装后面要用的命令：`euler`、`euler-team`、`euler-milestones`，以及工作台服务。每打开一个新终端，都要先进入 `Euler-Agent` 文件夹并运行 `source .venv/bin/activate`，再使用这些命令。

## 3. 登录模型命令行工具

安装并登录你准备使用的 CLI：

| 团队中的 `provider` | 可执行命令 | 登录方式 |
| --- | --- | --- |
| `codex` | `codex` | `codex login`，或使用已配置的 API 认证 |
| `claude-code`（也接受 `claude`） | `claude` | `claude auth login` |
| `gemini` | `gemini` | 首次运行 `gemini`，选择 Google 登录 |
| `grok` | `grok` | `grok login` |
| `cursor` | `cursor-agent` | `cursor-agent login` |

安装说明见 [Codex](https://github.com/openai/codex)、[Claude Code](https://code.claude.com/docs/en/setup)、[Gemini CLI](https://geminicli.com/docs/get-started/installation/)、Grok、[Cursor](https://cursor.com/docs/cli/installation)。Gemini 团队适配使用 0.63 的 ACP 与会话存储接口；Cursor 需提供 `acp` 与 `session/load` 接口。Euler 的适配与验证范围见 `docs/CLI-SUPPORT.md`。

无本地浏览器的远程机器可使用相应 CLI 的设备登录流程，例如 `codex login --device-auth`。凭据保存在本机服务商配置中，按需提供给成员私有运行目录或系统 Keychain，不进入里程碑或网页。

填写账户可用的模型名。Codex、Claude、Grok 使用各自的推理强度选项；Gemini 与 Cursor 的 `effort` 填 `model-defined`，模型及其支持的参数由所填模型标识决定。Cursor 可通过 `cursor-agent models` 查看模型标识。

## 4. 描述你的问题和团队

一个项目的一切都从一个定义文件开始。在 `Euler-Agent` 文件夹中复制示例，然后编辑副本：

```bash
mkdir -p ~/euler-research
cp examples/personal-research/research.json ~/euler-research/euclid.json
```

最常修改的字段：

| 字段 | 含义 |
| --- | --- |
| `id`、`title` | 简短标识（字母、数字、`-`、`_`），以及工作台中显示的名称。 |
| `problem.statement` | 团队要处理的精确命题。请仔细书写：它对这个项目是固定的。 |
| `problem.assumptions`、`parameter_domain`、`definitions`、`quantifiers` | 适用范围：假设条件、变量的取值范围，以及所采用的定义。 |
| `problem.target_kind` | `PROOF`、`COUNTEREXAMPLE`、`CLASSIFICATION` 或 `FORMALIZATION`。 |
| `problem.required_evidence_level` | 关闭目标所需的检查证据类型，例如 `LLM_CHECKED_PROOF`（独立的证明检查）或 `KERNEL_CHECKED_PROOF`（Lean 内核检查）。 |
| `team.members` | 恰好一个 `lead`（主 Agent），以及若干助手。每位成员可选择 `codex`、`claude-code`、`gemini`、`grok` 或 `cursor`，填写模型、推理强度与分工；不强制包含 Codex。 |
| `team.max_turns` | 可选的工作区总轮次上限；不设置或填 `null` 时不限制。你的每个提问和主 Agent 的每次咨询都各算一轮。 |
| `team.members[].max_turns` | 可选的单个成员轮次上限；不设置时不限制。 |
| `team.turn_seconds` | 每一轮非 Grok 工作的时间上限（10–3600 秒）。Grok 轮次没有固定时限，会一直运行到完成或你暂停团队。 |
| `task_budget` | Euler 自己调度任务的账本，例如可选的单项任务。它不限制团队对话。 |
| `workbench` | 工作台的地址和端口。主机请保持 `127.0.0.1`。 |

以后若要修改命题或范围，请用修改后的定义新建一个项目。团队及其记录都绑定在最初的精确命题上。

## 5. 创建工作区

```bash
python examples/personal-research/create_workspace.py \
  --definition ~/euler-research/euclid.json \
  --workspace ~/euler-research/euclid
```

这一步只需一秒左右，不会联系任何模型服务。它拒绝写入已有文件的文件夹，因此不会覆盖已有工作。它会创建：

```
~/euler-research/euclid/
  projects/euclid-primes/   项目：命题、范围、主目标、团队名单
  history/euclid-primes/    里程碑使用的私有 Git 历史（位于项目之外）
  workbench/                工作台设置与 start-workbench.sh
  setup/                    实际使用的输入（contract.json、policy.json、team.json）
```

脚本会初始化精确的问题契约，创建待闭合的主目标，注册团队，并写好工作台配置；不需要再手动重复初始化。缺少 CLI、登录文件或 Landlock 支持时，它会给出提示，这个检查不会联系模型服务。

## 6. 连接团队并打开工作台

为每位成员连接原生会话。这会按成员配置连接会话，不会向模型提问。Claude 会先准备运行环境，在首次发送时创建或分叉原生会话：

```bash
EULER_RESEARCH_PROJECT="$HOME/euler-research/euclid/projects/euclid-primes"
euler-team prepare --project "$EULER_RESEARCH_PROJECT"
```

成功后，团队状态变为**团队就绪**，Euler 也会自动保存一个里程碑。如果失败，提示会指出是哪位成员以及原因（见第 20 节）。

在一个可以一直开着的终端里（例如 `tmux`）启动工作台：

```bash
bash ~/euler-research/euclid/workbench/start-workbench.sh
```

打开 `http://127.0.0.1:8130`。页面只负责读取和展示，启动它不会启动团队。

**本机运行。** 如果团队就在这台 Mac 或 Linux 电脑上，直接打开上述地址即可，无需 SSH 转发。

**从另一台电脑访问。** 让工作台保持在 `127.0.0.1` 上，通过 SSH 转发端口。在 Mac 上运行：

```bash
ssh -N -L 8130:127.0.0.1:8130 you@your-linux-computer
```

然后在 Mac 上打开 `http://127.0.0.1:8130`。这通过 SSH 连接使用你自己的研究主机，不需要另填工作台密码。已经配置好的个人私网工作台地址也可以继续使用。

也可以不用命令行，改在浏览器里连接会话：**团队交互 → 连接成员会话**（首次连接），或**恢复本分支的成员会话**（恢复分支） 与 `euler-team prepare` 的作用相同。

### 从网页新建项目

工作台启动后，点击顶部研究里程碑旁的**创建项目**。填写项目名，选择主 Agent 的 CLI、模型和推理强度，再写下第一条研究需求。点击**创建并开始对话**后，页面会切换到新项目的**团队交互**：先显示会话准备状态，再显示主 Agent 的回复。每个项目都有独立目录、研究记录和团队会话；后续项目无需重复手动填写初始化文件。

## 7. 提出第一个问题

1. 点击页面顶部的**团队交互**。
2. 在左侧成员列表中选择主 Agent（`codex · 主 Agent`）。
3. 在**你的问题**中输入问题。以示例项目为例：

   > Propose a short proof plan for the main goal. Record its steps with euler_team_propose_steps, then ask grok with euler_team_ask to check the step about a prime divisor of N! + 1. When grok's reply arrives, summarize what it found. Do not claim that any step is verified.

   （问题也可以用中文写；成员会按原文阅读。）
4. 点击**发送**。

工作在运行团队的 Mac 或 Linux 主机上进行。主 Agent 先工作一轮；当它咨询助手时，助手工作一轮，助手的回复会交回主 Agent，主 Agent 再工作一轮。因此这样一个问题通常要用三轮。回复显示在右侧选定成员的聊天记录中；页面会每三秒检查活动对话。你可以关闭浏览器，工作会继续。

每一轮可能需要好几分钟。主 Agent 工作时，成员列表显示**工作中**，最新的消息显示**进行中**或**排队中**。

## 8. 一开始会看到什么

新项目看起来几乎是空的，这是正常的。

- **第一个计划之前：** 概览只有一张标着**待闭合**的**主目标**卡片，汇总显示**主目标尚未闭合**，各证据层级都是零。运行诊断列出创建项目时的事件：问题契约、主目标义务和任务预算。
- **主 Agent 记录计划之后：** 主目标下多出一条**证明路线**（标为**已提出**），路线的各个步骤显示为标着**待闭合**的**证明模块**卡片。连线把每个步骤连到路线，再把路线连到主目标。研究现场显示“新研究路线已登记”。

这些记录最初都处于提议阶段。第 10 节说明如何登记验证证据，将步骤更新为**已闭合**。

## 9. 六个页面

项目名下方有六个同级入口。研究视图在开启**实时同步**时每 15 秒刷新；团队交互中的活动对话每 3 秒检查一次。

### 概览：证明进行到哪里了？

- 页首显示项目标题和**主目标原始陈述**；点击**展开原文**可查看你写下的精确命题。
- **主目标验收状态**说明主目标是否已有验收通过的记录，并链接到主目标。证明写完、队友认为正确、主目标通过验收是不同阶段；没有登记验收结果时仍显示“尚未闭合”。
- **证明结构**从左到右画出已记录的证明架构：基础步骤、路线和主目标。每张卡片显示类型、状态以及它下面有多少条记录（例如“下层 3 项 · 3 项待闭合”）。连线是已记录的依赖，从前提指向使用它的结论。点击卡片，右侧会打开它的摘要面板。
- **证据层级**分别统计五类记录：提出路线、作者自报、已接受证据、已检查组件、主目标闭合。每个层级分别依据对应的证据和验收要求统计。
- **证明路线**列出为达成目标而提出的方法，以及每条路线还需要多少前提。主目标闭合需要对应的最终验收记录。
- **研究现场 · 正在发生**显示成员、他们的分工和最新的公开记录。
- **从这里开始读**给出建议的阅读顺序。

### 证明阅读：这一步到底说了什么，为什么成立？

阅读器一次只显示一条记录。左侧目录把记录分组（主目标、待闭合步骤、路线、已闭合步骤），并可筛选。选中的记录会依次显示：

- **陈述 · 原始记录**：当初记录的原文。
- **① 用到什么 · 直接前提**
- **② 如何得到 · 推导依据**：如有记录，显示原始论证。如果是提议，会直接说明（“这条记录没有附原始证明正文”），并列出已记录的路线及其步骤。
- **③ 如何核验 · 登记的验收证据**
- **④ 接下来支持什么**

**回到主目标**、**返回上一步**和**复制此步链接**帮助你移动位置并分享当前所在。

### 研究现场：现在正在发生什么？

这里列出成员及其分工、待解决的路线和问题，以及研究动态，例如新路线、尝试、障碍和结果。与团队的对话不在这里，而在**团队交互**中。

### 关系图：所有东西是怎样连起来的？

关系图画出所有已记录的节点和关系。

- **主线**显示通往主目标的依赖，**前沿**显示仍待推进的地方，**全部记录**显示一切。
- **研究记录**是由目标、步骤和路线组成的工作图；**入库事实**只显示通过 Euler 检查的结果。
- 左侧面板有**导读**、**关系**列表和**节点**列表。按 `/` 可以搜索。

### 运行诊断：系统运转是否正常？

运行诊断列出配置的成员和控制事件日志，例如契约、新义务和新路线。这里成员可能显示“状态未知”；团队的实时状态请看**团队交互**。通过运行诊断查看执行情况，通过证明阅读查看数学依据。

### 团队交互：项目 → 分支 → 成员

这是与另外五个页面并列的独立对话入口。左侧先标明项目和当前分支，再列出这个分支的成员。展开“分支”可切换原工作区和恢复分支；选择成员后，右侧显示这位成员的提问、公开回复及协作消息，底部输入框用于继续对话。

点击左侧成员列表下方的**＋ 添加成员**，可指定成员名称、CLI、模型、推理强度和分工。新成员只加入当前分支，收到第一条消息时自动连接会话。你也可以直接要求主 Agent 添加成员，例如“添加一个 Grok 助手来检查边界情况”；主 Agent 可以通过团队工具注册配置明确的成员并向它分配任务。成员加入记录和原生会话会一起进入后续里程碑。

“已保存的历史”标出从里程碑继承的消息，“本分支从这里开始”区分后续工作。父分支或其他分支后来产生的对话不会混入这里。点击“显示更早的消息”可继续查看历史。每个分支、每位成员的草稿分别保存在当前浏览器标签页中，切换页面或刷新也会保留。阅读旧消息时，新回复会通过提示按钮提醒，不会强行把页面拉到底部。

### 状态标签的含义

| 标签 | 含义 |
| --- | --- |
| **待闭合** | 需要成立，但尚未被接受。 |
| **已提出** | 有人提出的一条路线或一个步骤。 |
| **推进中** | 有人正在处理。 |
| **受阻** | 在等待别的东西，原因可能是数学上的、运行上的或额度上的。 |
| **已闭合** | 已凭所要求类型的登记证据被接受。 |
| **已搁置**、**已反驳**、**记录失效** | 被放到一边；被证明为假；或因依赖的内容改变而不再有效。 |
| **检查未通过**、**检查结果未确认** | 证据已登记，但检查没有通过或没有结果。 |
| **资料支持** | 出现在依据原始资料整理的历史归档中。 |

通过主目标及其待证前提判断进度。一个关键步骤是否解决，就可能决定整个目标能否闭合。

## 10. 一个步骤怎样变成“已闭合”

团队成员负责编写草稿、审阅论证并记录提议。Euler 登记了满足问题契约所要求级别的验证证据后，步骤会更新为**已闭合**。对 `LLM_CHECKED_PROOF` 来说，这意味着通过 Euler 验证服务做一次独立的证明检查；对 `KERNEL_CHECKED_PROOF` 来说，意味着一次 Lean 内核检查。这些验证工具需要单独配置，不在本指南的第一条路径之内；相关命令（`euler kernel-check`、`euler admit-fact`）见 `docs/cli-and-tools.md`。

在那之前，请你自己阅读团队写的草稿。成员把文件写在项目文件夹里，例如主 Agent 的工作文件夹是 `projects/euclid-primes/workers/codex/`。里程碑会保存这些文件。工作台展示已登记的 Euler 记录及其验证结果；其他文件可以在项目文件夹中查阅。

## 11. 跟随一个步骤及其证明路径

1. 在概览的**证明结构**里点击一张卡片。右侧面板会显示该步骤的陈述、它下面有什么、是否有原始论证，以及最近的记录。
2. 选择**阅读前提、论证与证据**在证明阅读中打开它，或选择**在关系图中定位**查看它的上下文。
3. 在关系图中点击一个节点，会打开**节点详情**，并高亮已记录的依赖链：上游前提为蓝色，下游结论为绿色。**整条依赖路径**只显示这条链。**一跳邻域**、**全部前提**、**全部下游**和**完整图谱**用于调整显示范围。**复制 ID** 复制记录的标识。
4. 点击两个节点之间的连线，可以查看这条关系的类型和已记录的理由。

高亮路径展示已记录的依赖关系。打开各步骤的论证和验证依据，可以检查推导内容及验收状态。

## 12. 原文与界面语言

界面默认使用英文。点击 **中文** 会把按钮、标题和说明切换成中文，并记住你的选择；也可以在地址中加 `?lang=en` 或 `?lang=zh` 直接设定。你的命题、团队的步骤和回复，以及你自己的提问，始终按原文显示，从不翻译。因此你读到的数学内容，就是当初记录的数学内容。

## 13. 页面刷新与实际运行的区别

页面每 15 秒读取一次记录（**实时同步**；关闭它只会停止刷新）。团队交互打开时每三秒检查活动对话的状态。读取从不启动工作。

只有三种情况会启动工作：

1. 你发送一个问题；
2. 主 Agent 在自己的某一轮中咨询另一位成员；
3. 你继续执行待办工作。

研究工作在 Mac 或 Linux 主机的后台进程中执行，浏览器或工作台关闭后仍会继续。请使用**暂停团队**或**终止团队**控制执行（第 17 节）。

## 14. 与团队对话

**谁收到你的问题。** 当前项目、当前分支中，左侧选中的那位成员，通常是主 Agent。直接向助手提问时，助手直接回答你。只有主 Agent 可以咨询其他成员、记录提议的步骤，所以需要全队配合的计划应该发给主 Agent。

**针对某一个步骤提问。** 在节点操作区选择“向当前团队追问”，会进入团队交互并附上这个步骤。它记录的原始命题、可用的范围信息和 ID 会随问题送入成员原生会话。你可以移除、更换这个附件，也可以直接在输入框上方附加证明步骤，无需打开终端。

**回复在哪里。** 就在右侧、当前选定成员的聊天记录中。消息先显示“排队中”，开始执行后显示“进行中”，完成后回复出现在对应消息下面。主 Agent 的咨询会注明发给了谁，并提供跳转到那位成员对话的入口。切换左侧成员即可查看各自历史。网络中断时可以明确重试，同一请求会复用标识，避免重复创建已收到的消息。

**成员记得什么。** 每位成员延续自己的原生对话，包括之前的问题和自己的回复。成员之间互相看不到对方的对话，除非通过咨询。

## 15. 保存里程碑

里程碑一起保存项目文件、研究图、任务、证据，以及每位成员的原生对话。它存放在项目之外的 `history/` 目录中，使用本地私有 Git 历史，且未配置远端。里程碑记录保存时的团队状态，各数学目标的验收状态由对应证据记录管理。

- **自动里程碑。** 会话连接之后，以及每当团队处理完待办工作、处于空闲状态时，只要有变化，Euler 就会保存一个 “Team state checkpoint”（团队状态检查点）。
- **命名里程碑。** 打开**研究里程碑**，展开**保存当前团队状态**，在**里程碑名称**中填写例如“计划已经 grok 审阅”，然后选择**创建 Git 里程碑**。团队必须处于空闲状态；如果还有一轮在运行，请稍后再试。

里程碑列表中，每一项会标明**含团队状态**或**仅文件**。只有含团队状态的里程碑能够接续成员的对话。

## 16. 从较早的时间点继续

当你想尝试另一个方向，又不想打扰当前工作时，使用这个功能。

1. 选中一个步骤（也可以不选），然后选择**从里程碑追问**，或者打开**研究里程碑**。
2. 选择一个里程碑。列表下方的说明会告诉你它是否包含成员的原生对话。
3. 可以写下你想追问的问题，然后选择**恢复完整工作区并准备追问**。
4. 网页会直接进入新分支的**团队交互**。左侧标明项目、当前分支及来源里程碑，右侧可以阅读继承的对话历史；原工作区保持不变。
5. 本分支显示**会话待恢复**，发送按钮暂不可用。选择**恢复本分支的成员会话**，Codex 和 Grok 创建原生会话分叉；Claude 在首次发送时创建分叉；Gemini 和 Cursor 从独立目录中的完整原生会话副本接续，保留服务商会话 ID。网页会标明具体恢复方式。成员接续里程碑当时保存的原生对话状态，不会复制原工作区之后新增的消息。
6. 保存的问题会作为未发送草稿放入主 Agent 的输入框。核对内容、选择合适的成员后点击**发送**。需要时可用保存问题的提示重新填入；点击**发送**后才开始处理问题。

恢复会保留所选里程碑当时的数学状态：当时未闭合的目标仍未闭合，已有的验收记录也一并保留。暂停和恢复过程中，证明的验收状态持续依据原有证据记录。

恢复出来的工作区会获得新的轮次额度，并有自己的里程碑。重启工作台后，它仍会保留在项目选择器中。

如果带着选中的步骤恢复时失败，提示 “selected object does not exist in this exact milestone”，说明这个步骤是在该里程碑之后才创建的。请选择较晚的里程碑，或不选步骤再恢复。

**三种继续方式的比较。**

| | 向当前团队追问 | 从里程碑追问 | 查看对象记录 |
| --- | --- | --- | --- |
| 在哪里 | 当前工作区，保持现状 | 保存点的一份全新、独立的副本 | 当前工作区 |
| 谁回答 | 你选择的成员，延续其对话 | 恢复出来的成员，从里程碑处延续其对话 | 没有人回答；它显示记录的精确版本、范围与证据 |
| 什么会启动工作 | **发送** | 恢复会话后点击**发送** | 查看记录；配置单项任务后可另行启动 |
| 用来做什么 | 推进当前这条研究线 | 探索另一种思路，或在轮次额度用完后继续 | 准确核对一个步骤说了什么、依赖什么 |

配置了单项任务时，第三项会显示为**查看对象 · 单项任务**。这时它可以为一个单独配置的 worker 准备一次受限任务：任务要先预览，只有按下它自己的启动按钮才会开始。示例工作区没有启用这一功能；如需设置，见 `docs/HUMAN-INTERVENTION.md`。

## 17. 暂停、额度与上限

会话连接之后，**团队交互 → 运行控制**提供三个按钮：

- **暂停团队**：中断当前这一轮，并保留排队中的问题。之后你新发送的问题仍会运行；被保留的问题要等你继续时才会运行。
- **继续待办任务**：放行被保留的问题并继续工作。
- **终止团队**：中断当前这一轮，并在你选择继续之前拒绝新的问题。

暂停和终止会更新执行状态，同时保留数学记录及其验收依据。

**目标与执行。** 每个成员的研究目标保存在团队状态中。使用 Codex 时还会保存其原生目标，并在对话模式中保持暂停。没有成员会自行继续：每一轮都从一个问题开始，要么是你的问题，要么是主 Agent 对另一位成员的咨询。

**自定义用量上限。** 如果设置了 `max_turns`，达到上限后 Euler 会停止派发对应团队或成员的新任务：对话页面会提示 “team turn allowance exhausted”，或者团队显示**本次轮次额度已用尽**。要继续，请恢复最新的里程碑（第 16 节）：恢复出来的工作区会获得新的额度。

**时间上限。** 超过 `turn_seconds` 的非 Grok 轮次会被中断，并标为**失败**。Grok 轮次没有固定时限。

## 18. 第二天回来继续

用 `start-workbench.sh` 重新启动工作台并打开页面。团队的会话保存在磁盘上，不需要重新连接。打开**团队交互**，继续提问即可。如果某个服务商让你重新登录，再运行一次它的登录命令；下一轮开始前，Euler 会复制新的登录文件。

如果电脑在某一轮进行中停机，那位成员可能一直显示**工作中**，队列也无法继续。这时请恢复最近的里程碑（它是在团队空闲时保存的），然后在恢复出来的工作区里继续。

让 `projects/`、`history/` 和 `workbench/` 留在脚本创建它们的位置。设置里用绝对路径指向这些文件夹，移动它们会使链接失效。

## 19. 没有保存对话的旧项目

工作台里的有些项目可能是导入的归档：已经完成、依据原始资料整理的研究，没有登记团队。你可以在研究视图里完整地阅读它们，但没有团队可以提问。它们的里程碑是**仅文件**的；恢复后，你会在新工作区里得到文件和关系图，但没有旧的对话。

Euler 从不用摘要或一个新的 Agent 冒充缺失的成员对话。这类归档中的步骤会显示“历史记录 · 此处只读”。

## 20. 遇到问题时

| 看到的提示 | 含义 | 处理方法 |
| --- | --- | --- |
| `native provider binary unavailable` | 进程的 PATH 中找不到 `codex` 或 `grok` 命令。 | 安装对应 CLI，或从能运行它的终端启动工作台。 |
| `Landlock ABI 3 or later is required` | 内核无法隔离 Agent 轮次。 | 换用启用了 Landlock 的较新 Linux 内核。 |
| `model drift while restoring`、`Grok configuration did not match` | 你的账户不提供成员使用的模型名。 | 在新的项目定义中改用 CLI 提供的模型（第 3 节）。 |
| `restore every team session before asking` | 有成员的会话还没有连接。 | 选择**恢复本分支的成员会话**，或运行 `euler-team prepare`。 |
| `team turn allowance exhausted` | 这个工作区的 `max_turns` 已用完。 | 恢复最新的里程碑，并在那里继续。 |
| `team must be explicitly resumed before new work` | 团队已终止，或因额度而暂停。 | 选择**继续待办任务**。 |
| 保存时提示 `team agent turn still running` | 还有一轮在进行中。 | 等回复到达后再保存。 |
| `This project is read-only in this deployment` | 启动工作台时没有带上这个项目的设置。 | 用 `start-workbench.sh` 启动。 |
| 团队交互显示“此工作区没有团队对话” | 这个工作区没有可接续的成员会话。 | 仍可阅读研究记录；已有注册团队的分支可从该入口对话。 |
| 打不开页面 | 本机服务未启动，或远程主机端口未转发。 | 本机运行启动脚本；远程访问时检查 SSH 转发。 |
| `macOS sandbox-exec unavailable` | 系统隔离工具不可用。 | 运行 `euler-team doctor` 检查；不会自动降级为无隔离运行。 |
| SSH 下 Cursor 提示登录钥匙串锁定 | macOS 尚未允许 CLI 使用登录凭据。 | 在 Mac 本机解锁登录钥匙串或通过 CLI 完成登录，再重试；网页不会索要钥匙串密码。 |

## 21. 在命令行里完成同样的操作

推荐在浏览器中工作。下面这些命令在 Mac 或 Linux 电脑上完成同样的事：

| 用途 | 命令 |
| --- | --- |
| 连接成员会话（不提任何问题） | `euler-team prepare --project "$EULER_RESEARCH_PROJECT"` |
| 查看团队、消息和回复 | `euler-team status --project "$EULER_RESEARCH_PROJECT"` |
| 向成员提问（会启动工作） | `euler-team ask --project "$EULER_RESEARCH_PROJECT" --member codex --question "…"` |
| 暂停、终止、继续 | `euler-team pause --project "$EULER_RESEARCH_PROJECT"`（`stop`、`resume` 用法相同） |
| 在命令行继续之后运行被保留的问题 | `euler-team run --project "$EULER_RESEARCH_PROJECT"` |
| 保存或列出里程碑 | `euler-milestones capture --project "$EULER_RESEARCH_PROJECT" --label "…"` / `euler-milestones list --project "$EULER_RESEARCH_PROJECT"` |
| 查看待闭合步骤、路线和证据 | `EULER_AGENTS_ROOT=~/euler-research/euclid/projects euler frontier euclid-primes` |

请在浏览器中恢复里程碑：浏览器会把新工作区登记到项目选择器中，并沿用团队设置。
