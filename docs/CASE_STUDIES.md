# Historical projects in the standard Euler workbench

Historical projects use the same overview, proof reader, live-research view,
relation map and diagnostics as native Euler projects. They are selected through
the existing project catalog. The cases share the standard workbench layout.

Set the server-owned `EULER_CASE_STUDIES_MANIFEST` to the frozen source manifest,
and set `case_study_id` in each applicable project's dashboard config. The
`historical_projection` adapter maps source-backed modules, routes, obstacles
and evidence into the existing read models. It provides a read-only projection alongside the original controller view.

Proof components use the distinct DOCUMENTED/Recorded state. Historical route
outcomes such as rejection, retirement and completion are displayed only where
the selected source stage supports them. The original controller status and
formal acceptance remain separate. Frozen source records keep their original evidence type and verification date.

Curated overview modules keep the first screen compact; the standard relation
map exposes the full source-supported dependency structure and historical
context. Each derived node opens in the existing proof reader with source-bound
explanation and original excerpts. The native live-research view includes the
selected historical O/R/B/E milestones alongside untouched shared records.

Source files must remain within the configured bundle and may not use symlinks.
A changed or unavailable source withdraws the derived structure. Source hashes establish record integrity; verification records establish the reported mathematical evidence level. Configured access controls and project isolation apply. Private campaign bundles remain deployment data.

Old `/static/cases.html` bookmarks redirect into the standard workbench.

## Existing acceptance evidence

A reviewed `verification_binding` can map a proof module to prior accepted Facts
or an archived kernel audit. Fact bindings require matching content hashes,
active admission and a successful original verification. Kernel bindings name
checked declarations and the complete source audit. They display the referenced checks with their original provenance. Invalidated bindings are
shown stale. Source-only nodes remain unverified.

The projection retains actual Fact predecessor edges and original verification
results. Main conclusions have explicit closing routes in the research read model;
where a final admitted Fact exists, it also anchors the Fact-layer main line.
All provenance remains inspectable in the ordinary reader and evidence details.
