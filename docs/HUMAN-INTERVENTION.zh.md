这一开发版本扩展了标准 Euler 工作台。研究者可以查看真实数学对象，预览精确的后续命题与范围，确认后明确启动一个有资源约束的聚焦任务。原有 Facts 和根问题约定继续遵循已有验证与验收规则。

## 整个团队的会话

[团队恢复流程](TEAM-RECOVERY.zh.md)在恢复完整工作区的同时，恢复已注册成员的原生会话。**向当前团队追问**打开针对具体成员的持久对话，包含负责人委派与返回回复。下述单项操作接口用于聚焦任务；整个团队的对话恢复要求已保存的原生会话归档。

## 单项任务界面点击启动后会发生什么

当前可执行路径是一个有界后台任务。选择原生对象会打开检查面板；提交已审阅的问题后，系统记录派生的问题约定和候选任务。明确点击启动时，系统检查对象版本、worker 配置、额度与就绪状态，再编译上下文，将任务派发到服务器上配置的 worker。页面显示任务状态及经过验证和协调回写的证据。

每个请求授权在所选工作区中执行一个有界操作。与负责人持续交流请用**团队交互**；恢复保存状态请用**研究里程碑**。未启用服务商启动时，单项任务接口只准备派发记录，等待后续执行。

直接派发要求对象具有规范的后台身份。历史展示节点可以阅读证明和恢复里程碑，弹窗会说明可用操作。恢复会话后，需要明确启动任务或发送问题才开始研究。

## 从真实研究项目开始

默认保留常规项目目录与完整证明／依赖图。通过 [Git 研究里程碑](RESEARCH-MILESTONES.zh.md)在团队空闲时保存全部文件，将指定提交恢复为独立工作区，再基于当时状态追问。对象与有明确范围的操作位于完整项目中，任务执行时仍可阅读完整图谱和历史。

## 独立的免账号协议演示

```sh
python -m pip install -e '.[dev]'
python -m euler.observability.human_demo --run-traces --serve --port 8124
```

程序打印的目录包含三个新初始化的原生项目、项目目录、请求样例、事件轨迹和公开结果。界面项目名、证明与验证工件均标注 MOCK。真实 HTTP API、子进程 worker、调度器／上下文／lease、Fact gateway 和协调回写流程由确定性的模型与验证者模拟程序驱动。子任务结果是预设的协议检查样例；原始目标保持 OPEN，父 campaign 保持 PAUSED。

打开证明阅读，选择**查看对象／单项任务**，检查身份、范围和证据并选择意图。输入问题和待研究的精确命题；若修改假设，编辑并审阅新的范围。预览、确认后，用独立的启动按钮执行。结果显示在源对象弹窗和研究现场的调查列表中，也可从弹窗导出事件轨迹。

## 为已有原生项目启用控制

1. 保留服务端持有的常规项目目录，不接受客户端指定路径。
2. 将 `config/human-control.example.json` 复制到部署专用配置。
3. 填入真实项目目录 ID 和已有 worker，使其服务商／模型／effort 与策略兼容，并设置资源限额。
4. 将 `EULER_HUMAN_CONFIG` 指向该文件。个人工作台无需额外的浏览器控制令牌；`EULER_CONTROL_ACTOR` 在事件来源中标识研究者，默认 `human:operator`。
5. `allow_launch: false` 仅允许准备任务；配置好原生服务商、额度及执行预检查规则后，才明确启用启动。
6. 在自己的机器或私有研究主机运行工作台。浏览器操作必须来自工作台同源页面；每个请求都遵守项目范围、资源限制和验证门禁。

默认只读。没有精确原生身份的历史／整理节点仍为只读，名称或语义相近不能代替身份映射。对 Fact 进行操作还需要明确验证的原生范围／约定绑定。Worker 的真值 gateway 保持唯一 Fact 入库路径；请求文本不能注入检查结果或任意操作者／模型配置。

## 生命周期语义

- Pause 禁止新的常规派发，已发出但尚未启动的常规 lease 会取消；正在运行的任务按所选模式等待结束或请求取消。
- 在相关 lease 实际结算前，PAUSING 和 STOP_REQUESTED 状态持续保留。
- 更新后的原生循环可终止本地子进程组；远端服务商的计算／计费可能继续，旧启动器可能需要操作者处理。Worker 观测状态与 lease 状态分别显示。
- 父 campaign 暂停时，可以明确启动聚焦任务，常规任务队列继续暂停。
- Stop 同时禁止新的聚焦任务，并请求取消已有聚焦任务。
- Resume 检查当前身份、未完成结算、已记录预算和依赖。尚未启动的已取消常规工作可以获得新 lease；已完成任务不盲目重放。中断中的任务保留工件与回执，需要恰当的新任务或恢复决策。
- 每次聚焦研究授权一个操作；再次尝试需审阅并授权新请求。

## API 与不变量

读取接口：`/api/human/capabilities`、`/object`、`/state`、`/interventions`、`/interventions/{id}`、`/changes`、`/compare`，均接受项目目录 ID。为个人项目配置后可用的写接口为 `/control`、`/preview`、`/interventions`、`/interventions/{id}/start`，不需要单独控制凭据，但仍检查同源和项目策略。Preview 本身是只读操作。

请求绑定来源对象 ID／类型、工作区命名空间、命题／范围／对象哈希、来源问题约定及版本、操作者身份和执行策略。对象变化后需要重新预览。预览还保守地绑定研究修订号，并发更新可能要求再次审阅。移动工作区会改变实例身份，需要新请求。

新的推广或反驳范围生成带父问题／来源链接的派生约定。挑战必须指明反驳目标，并使用能够支持反例的证据；原问题保留其命题和范围。相同请求重试返回原操作，幂等标识相同但内容冲突的请求被拒绝。

来源上下文通过现有有界编译器构建。父问题的检查工件在确认适用于子问题前，仅作为来源材料。协调回写把结果绑定到精确 lease、上下文和来源，返回已接受的子问题证据或未解决状态。重新审计已有 Facts 需要本次尝试的新验证；Fact 入库与撤销遵循已有验证程序。

## 证据与评估

子系统测试与确定性模拟演示检查控制流程。关于人类理解和 Agent 效率的受控研究仍在规划中；多用户角色、自动范围等价判断和不限制操作数量的聚焦 campaign 属于后续工作。部署额度监控追踪账户报告的使用量，计费上限请通过服务商账户控制设置。

演示停止后，使用 `--reuse --output /path/printed/by/the/demo --serve` 可从保留记录重新打开。使用 `--run-traces` 时应指定新的输出目录，使每次协议测量有明确的起始状态。原生轮次时限不包含调度器和预检查开销。页面刷新后，尚未完成的浏览器提交仍保留其幂等身份。
